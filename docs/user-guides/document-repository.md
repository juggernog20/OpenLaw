# Find Documents in the repository

Use **Documents** to find paper across the owning records you can reach, then open the matching current Version on its record.

## Before you start

Legal Team Members and Administrators can find reached Contract, Matter, Entity, Auto-Doc, and Knowledge Documents. Business Users read permitted paper through Portal records, Requests and Knowledge.

The repository is a flat view. Uploads and folder management start on the [owning record](document-versions.md). You can drag a live Contract, Matter, or Entity Document row onto a **Move to folder** target to move it inside its owning record. Confidentiality and record access still apply to results and filter choices.

## Search and narrow the list

1. Open **Documents** from navigation. **Recent** shows up to five Documents whose current Versions were uploaded most recently; it does not mean recently opened.
2. Select **Filter** above the list. Choose **Owner** to narrow to **Contracts**, **Matters**, **Entities**, **Auto-Docs**, or **Knowledge**, then select **Apply**.
3. To choose one owning record, use **Record**, type its reference or title in **Search choices**, select the match, and select **Apply**. A **Folder** filter becomes available for one Contract, Matter, or Entity; **Record root** means paper outside its folders.
4. Combine **Format**, **Kind**, **Counterparty**, **Uploader**, and **Uploaded** as needed. In **Format**, **Kind**, **Counterparty**, and **Uploader**, you can select several values; a Document matches any selected value. Different active filters must all match. **Uploaded** takes a **From** date, a **To** date, or both. The dates include both endpoints and refer to the current Version's upload date.
5. Remove an individual filter or select **Clear all** to widen the results. Recent documents is hidden while filters are active.

Kind, uploader, format, and dates describe the current Version. A Counterparty filter follows its Contract relationship; it does not create Counterparties on Matters or Entities. Knowledge and Auto-Doc Documents have no Document folders. Knowledge Folders organize items instead.

Use [saved views and list controls](search-and-views.md) for reusable layouts. For words inside an earlier Version or an OCR'd scan, use global search; repository filters are not a complete search of every historical Version's contents.

## Open the matching paper

Select the Document row's open action or name. Its owning record opens with the current Version selected. Check the reader's Version number; expand the Document's chain on the record to select an earlier round. The owning-record reference identifies where the paper belongs.

## Missing or archived Documents

A Legal Team Member or Administrator can select **Filter**, then **Show archived**, to include archived Documents. Use the offered **Restore** action when permitted, or open the owning record and follow [archive and restore](archive-and-delete-documents.md). Restore the owning record first if it is archived.

Business Users are not offered archived Document management. A hidden record or Document does not become visible through a filter, saved view, or direct link. If the list is empty, clear filters, check the intended owner and current Version properties, then ask the responsible Legal Team Member about access or archive status. A permanently deleted Document cannot be restored from this view.
