# OpenLaw — Future Features

Parking lot for features and ideas explicitly deferred out of v1. Each entry records where the deferral was decided (if anywhere) so the context isn't lost when we pick it back up. This is a wishlist, not a commitment — items graduate by getting their own grill and decision record.

Add entries freely during grills; keep each to a few lines.

| Feature                                        | Origin                                                                  | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SLA engine for matters**                     | MTR-004 (2026-08-02)                                                    | Per-type response-time targets, breach clocks that pause while a matter is On Hold (`open`-category statuses may need a "paused" flag then), SLA dashboards. v1 ships named key dates only; the `matter_key_dates` table and MTR-002's status categories were shaped so an SLA layer can bolt on without remodeling.                                                                                                                                                      |
| **Reporting as a destination**                 | DD-005                                                                  | Dashboards/reporting as a first-class nav destination was rejected for v1 (cross-cutting dashboards only). Revisit once modules have real data shapes. The Reports nav item in the contract-details mock is a known conflict pending removal/parking.                                                                                                                                                                                                                     |
| **Cmd-K command palette**                      | DES-010                                                                 | Deferred; v1 keyboard surface is `/` (search), `Esc`, `?`. Revisit once there are enough commands to palette over.                                                                                                                                                                                                                                                                                                                                                        |
| **Outside-counsel spend / e-billing**          | MTR-006 (2026-08-02)                                                    | Budgets, accruals, invoice review, UTBMS/LEDES e-billing. v1 handles external counsel as Contributor users only (collaboration, no money). A future module attaches spend to matters and likely needs a law-firm-flavored counterparty record.                                                                                                                                                                                                                            |
| **Retention / redaction policies**             | MTR-008 (2026-08-02)                                                    | Automatic retention rules (e.g., purge closed matters after N years), scheduled redaction, legal-hold exemptions. v1: hard delete is a manual Admin compliance action only, logged per DD-017. Useful for privacy-conscious deployments (GDPR storage limitation).                                                                                                                                                                                                        |
| **Tags (matters + documents)**                 | MTR-010 (2026-08-02), DOC-007 (2026-08-04)                              | Flat org-wide tags for cross-type grouping (deals, themes, occasions). If graduated: Member+ creates inline, Admin curates (rename/merge/archive) in settings. Tables (`tags`, `matter_tags`, `document_tags`); nothing in v1 depends on them. DOC-007 extends the deferral to documents — PRODUCT.md's repository "tagging" wording is satisfied when this graduates (or amend the wording).                                                                             |
| **Approval rules engine (thresholds)**         | CTR-012 (2026-08-02)                                                    | Declarative rules ("MSA ≥ $100k → GC approves") that _pre-apply_ approver groups when a contract enters the approval stage. Natural layer on top of CTR-012's groups; declined for v1 in favor of manual + group templates.                                                                                                                                                                                                                                               |
| **Contract templates**                         | CTR-017 (2026-08-02)                                                    | MTR-013-shaped templates for contracts: per-type pre-fill (priority, risk, term_type, custom fields, title prefix) + template tasks with relative due dates and role targeting (contract owner). Deferred until real usage shows which playbooks teams want.                                                                                                                                                                                                              |
| **Additional e-signature adapters**            | CTR-013 (2026-08-02)                                                    | Documenso / DocuSeal (self-hostable OSS), Dropbox Sign, Adobe Sign behind the CTR-013 signing adapter. DocuSign ships first.                                                                                                                                                                                                                                                                                                                                              |
| **Conditional custom-field logic**             | MTR-014 (2026-08-02)                                                    | "Show field B only if field A = X" on matter forms (Legal Tracker "smart matters"). A dependency-graph engine with real edge cases (cycles, hidden-but-required, stale hidden values); none of the small-team competitors ship it.                                                                                                                                                                                                                                        |
| **Derived key dates**                          | Matters research grill (2026-08-02)                                     | A key date defined as an offset from another ("Response = Service date + 21 days"), auto-recomputing when the trigger moves (Clio Court Rules pattern, minus the jurisdiction library). Deferred for matters. **Partially promoted:** the Contracts grill adopted the strongest case as a built-in — the derived notice deadline (`expiry − notice_period_days`, CTR-006, never stored). General user-defined derived dates remain parked.                                |
| **Outside-counsel evaluations**                | Matters research grill (2026-08-02)                                     | Lightweight 1–5 firm rating prompted at matter close (Legal Tracker pattern); aggregates into a firm scorecard. Needs >3 firms in play to matter; pairs with the e-billing/spend module.                                                                                                                                                                                                                                                                                  |
| **Legal holds**                                | Matters research grill (2026-08-02)                                     | Candidate future _module_, not a Matters feature: templated hold notice to N custodians, acknowledgment tracking, reminders, release, audit log. All researched vendors sell it as its own product; the lightweight version above covers small teams.                                                                                                                                                                                                                     |
| **Time tracking on matters**                   | Matters research grill (2026-08-02)                                     | LawVu-style time entries per matter (visibility, not billing). No current demand signal; revisit if workload reporting needs it.                                                                                                                                                                                                                                                                                                                                          |
| **Capacity / workload dashboard**              | Matters research grill (2026-08-02)                                     | Xakia-style per-lawyer RAG workload indicator (volume × complexity) with the intake queue displayed alongside; plus the "Quadrant" (strategic value × complexity scatter). Belongs to the dashboards capability (DD-005) when that gets designed.                                                                                                                                                                                                                         |
| **Email-to-intake capture**                    | INT-001 (2026-08-04)                                                    | Inbound email parsing (`intake@`) was dropped from v1 — structured forms are the only capture. Future version should pair with AI extraction: parse the email, pre-fill the structured form, requester confirms in the portal. DD-010's transport research (IMAP/webhook/SMTP-forward) still applies when revived.                                                                                                                                                        |
| **Email filing to existing matters/contracts** | Matters research grill (2026-08-02), INT queue disposition (2026-08-05) | Forward/BCC correspondence onto a record's timeline — per-record addresses (`m-42@…`, LawVu pattern) or mail-client add-ins; the most-praised feature category across researched competitors. Requires inbound email infrastructure, which INT-001 dropped from v1 — revive together with email-to-intake capture.                                                                                                                                                        |
| **ChatOps capture (Slack/Teams)**              | INT-001 (2026-08-04)                                                    | DD-010's ChatAdapter capture+bridge ambition shrunk to at-most notifications + deep-links to the portal form. Full chat capture (Halp/Linear-Asks bridge) parked; revisit if portal adoption stalls at chat-heavy teams.                                                                                                                                                                                                                                                  |
| **Share registers / cap tables**               | ENT-001 (2026-08-06)                                                    | Share classes, issuances, certificates, transfers, shareholder ledgers (Diligent-parity corporate secretarial). v1 keeps three simple share-capital fields.                                                                                                                                                                                                                                                                                                               |
| **Knowledge intelligence**                     | KNW-004/005 (2026-08-06)                                                | In-workflow surfacing (template picker at contract creation, clause suggestions in review), semantic/vector search, usage tracking (“inserted into C-42”), stale-content review-by rules, AI authoring/retrieval, external clause-library ingestion. All presuppose a populated corpus.                                                                                                                                                                                   |
| **Settings delegation**                        | SET-002 (2026-08-05)                                                    | Per-surface grants letting Members manage low-risk org settings (templates, deflection links, approver groups) without Admin role. Adds a grants concept to DD-013's four-role scheme — deferred until team-size demand appears.                                                                                                                                                                                                                                          |
| **Self-service email change**                  | SET-006 (2026-08-10)                                                    | Changing your own sign-in email from the Profile pane. Needs a verify-both-addresses flow (better-auth `changeEmail` is not configured) and churns the identity the DD-010 allowlist and invites key on. v1 workaround is admin-driven: archive the user and re-invite under the new address.                                                                                                                                                                             |
| **Open in Word / LibreOffice**                 | Documents idea (2026-08-08)                                             | Open a stored document directly in the user's desktop editor (Word / LibreOffice) instead of download-edit-reupload; when the document is closed, the edited file is saved back automatically as a new version in the DOC-001 immutable chain. Mechanism candidates when graduated: WebDAV (`ms-word:ofe\|u\|` / `vnd.libreoffice.command:` protocol handlers) or a desktop companion/sync agent; locking/conflict story needed since DOC-001 chains are strictly linear. |
| **AI assistance on matters**                   | Matters research grill (2026-08-02)                                     | Matter summarization, intake auto-classification/extraction, "intelligent status update" (infer status from activity — Checkbox). For self-hosted OSS: optional bring-your-own-key integration. The one pattern all vendors converged on first is intake extraction (email → pre-filled fields). **Partially promoted:** AI _contract_ analysis (BYO key, field-schema-driven extraction) is now in scope per CTR-008; matter/intake AI remains parked here.              |
