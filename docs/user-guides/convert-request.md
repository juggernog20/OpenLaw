# Convert a Request to a Contract

Create a Contract from a Request and check the information, paper, and conversation that follow it.

## Before you start

- Sign in as a Legal Team Member or Administrator.
- Have an undecided Request that targets a Contract. Review the Request and its attachments before converting it.
- Have a live Contract type and any required information the form did not collect.

## Convert the Request

1. Open the Request from **Inbox**. Open **Triage** and select **Convert to contract**.
2. Check **Title**, which starts with the Request's Summary, and **Priority**, which starts with the Requester's Urgency. Edit them if needed.
3. Check **Contract type**. A live type configured on the request form is already selected. If the form left the type open, choose a live type now.
4. Review **Carries into the contract** and **Does not carry into the contract**. Answers carry only where the destination type has the corresponding Fields. Other answers remain readable on the Request.
5. Complete any required Fields the form did not collect. If a carried reference is marked archived, choose a live replacement where the dialog asks for one.
6. Select **Convert to contract**. This decides the Request and creates the Contract. Use **Cancel** before confirming if you are not ready.

## Check the result

Open the new Contract from the recorded outcome. Check its Title, type, and Priority, then select **Fields** to check the carried answers. In the example form, **Owning department** should still say **Procurement**. The Request's Description remains on the original Request; conversion does not copy it into the Contract's Description.

Select **Documents** and check that each Request attachment became a Document with the expected filename and contents. Open **Comments** and confirm that the conversation is present. Visibility tiers remain in effect: a Legal Only comment must not appear to the Business User.

The Requester keeps the original Request address in the Portal. That same R- address now shows **In progress** and continues the conversation available to that person. Conversion does not grant the Business User access to the staff Contract page.

## If it does not work

If the dialog marks a missing required answer, provide it before trying again. If it says someone else already decided the Request, close the dialog and read their outcome; do not create a second Contract to repeat the conversion.

If an answer is listed as not carrying, it is retained on the Request. Check the destination type's Field configuration with an Administrator before assuming that the Contract contains it.
